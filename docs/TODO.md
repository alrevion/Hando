# Что решено сделать, но ещё не сделано

## Зависимости задач: «нельзя начать, пока не сделано предыдущее»

Владелец: «нельзя поливать цветы Ларисы Сергеевны, пока не политы цветы бабули».

### Что уже есть

Движок написан и работает — это не «с нуля».

- `tasks.depends_on_task_id` — ОДИН предшественник, обязательно из того же
  проекта (`resolveDependency`, `src/routes.ts:1396`).
- Переход блокируется на «принять»: `src/routes.ts:1663` и голосом
  `src/intake.ts:292`. Пока предшественник не `done`/`archived` — отказ 409.
- Приложение показывает блокировку в списке задач (`MyTasksView`, `blockedBy`).

### Чего нет

1. **Задать зависимость нечем.** API поле принимает, но в карточке черновика
   такого выбора нет, голосом не сказать, в боте кнопки нет. Поле заполняется
   только через прямой запрос к API — то есть никем.
2. **Текст отказа английский**: `blocked: "…" must be finished first`. Он
   доходит до человека тостом.
3. **Блокируется не тот этап.** Сейчас нельзя ПРИНЯТЬ задачу. Но принять — это
   всего лишь «увидел, берусь»; логичнее пускать в «принято» и запрещать
   «взять в работу». Иначе задача выглядит недоступной ещё до того, как человек
   вообще о ней узнал.
4. **Только один предшественник и только внутри проекта.** Для «цветы бабули»
   и «цветы Ларисы Сергеевны» в разных отделах не сработает.

### Открытые вопросы

- Как называть это словами для завхоза? «После чего» понятнее, чем
  «зависимость».
- Показывать ли заблокированную задачу в «К выполнению» или прятать до
  разблокировки. Прятать опаснее: о задаче забудут.
- Нужна ли цепочка длиннее двух звеньев и что делать с кругом (A после B,
  B после A) — сейчас `resolveDependency` запрещает только ссылку на себя.
